Rust bridge uses existing al_ipa_editor_run JSON. imported_loads input=extracted .app, executable=main filename, output=JSON file. Result {version:1,entries:[{owner,main_owner,slice,subtype,load_path,weak,resolved_path}],warning}. owner/resolved_path are app-relative; null resolved_path means unresolved, never guessed by basename. These are imported non-system dependencies, NOT proof of injection. Each arm64/arm64e FAT slice gets separate entries.
edit_imported_loads input=immutable extracted original .app, executable=main filename, output=NONEXISTENT working .app, edits=[{owner,remove:[load_path],order:[load_path]}]. Edits apply consistently to every arm64 slice in that owner. order if nonempty must list every remaining non-system load exactly once, and all slices must agree. Removed commands compact in place; no relocation. Files intentionally retained (including shared frameworks); warning explicitly states this. This avoids deleting assets still referenced by non-arm64 code or unknown dynamic lookups. Reset/undo discard working output and rebuild from immutable original with prior edits / empty edits. Original never written, failure removes only newly created working output. Repack working copy using existing pack operation. Editing signed binaries requires re-signing.
Critical editing gate, actual symbol bindings encode dylib ordinals. Binaries with nonempty dyld bind/weak/lazy streams, chained fixups or symbol tables are refused with explicit 'Dependency editing requires dyld ordinal rebinding...' rather than corrupting imports. Inspection still works. Therefore this implementation is NOT a complete arbitrary real-app removal/reorder solution. Frontend must surface the error, not claim success. Modern apps generally need a future verified ordinal rebinder before editing; deterministic fixtures without binding payloads exercise real command mutation safely.
Contract revision after review, each edit may set delete_files:true (default false). Only contained .dylib Mach-O files, never main executable or framework bundles, are candidates. File is deleted only if every inspected owner architecture is arm64, the complete remaining non-system dependency graph resolves, and no owner/slice still refers to that target. Otherwise file remains. Owner+main LC_RPATH anchors are resolved only within bundle with a single existing candidate; ambiguous/unhandled lookup stays null. Missing direct links likewise stay null. 32-bit/x86-only owners are not listed and prevent file deletion; malformed FAT still fails closed.
Local proof, scripts/test_imported_loads.py compiles actual module and extracted unchanged production parser with serde using offline Cargo. This is not full rust-core/FFI or device compilation. Physical device untested. No pushes/publication.
