Mirsa own loader, private backend contract

Operation `inject_loader` on the existing al_ipa_editor_run JSON bridge accepts input app directory, executable basename, ordered libraries array and new_first. Default existing `inject` operation is unchanged. Parent integrator owns Swift choice and must call inject_loader only when the user explicitly selects loader mode; retain direct by default. No extra FFI symbols or shared Swift changes here.

This is a small own implementation, NOT LCSign's runtime, and offers ordered constructor loading only. No switch-after-install, crash recovery, logging or LCSign feature parity is claimed. Re-sign/reinstall for changes. Input order is preserved; dependencies must be earlier than dependent roots, cycles and eager app loads into managed roots fail. 1–64 roots, thin arm64 iOS only, iOS 15 minimum. FAT, arm64e and missing external hooking dependencies fail closed rather than bundling substitutes. The current conservative dependency resolver cannot model arbitrary runpath stacks and rejects unresolved paths. Framework resources copy unchanged through the existing injector; symlinks and special files reject.

Backend embeds loader/MirsaLoader.dylib built from our C source. It copies tweaks into Frameworks, emits Frameworks/MirsaLoadOrder.txt, removes direct main-executable load refs for these roots and adds exactly one @loader_path/Frameworks/MirsaLoader.dylib reference. Never execute tweak binaries on build host. Use only on disposable app copy. Any error means discard copy, since ordinary inject and validation can already have changed it.

Build loader with loader/build.sh. Linux uses clang-21 plus ld64.lld-21 and our minimal public ABI declarations / libSystem link interface, not a copied SDK or proprietary binary. Darwin uses xcrun iphoneos clang. Cross-built loader is deliberately unsigned and must be signed by existing inside-out application signer along with every nested Mach-O BEFORE outer app sealing. No additional entitlements and no profile changes are introduced; existing certificate/profile checks remain mandatory. Signature/CMS and final generated IPA installation have NOT been device-tested here. Existing signing engine performs actual nested signing; integrator must confirm loader included in nested signing traversal and verify final IPA and signatures on CI.

A dlopen failure stops later roots, but earlier constructors cannot be undone. Loader handles intentionally persist for process lifetime. Existing app libraries initialize before this loader according to dyld dependency scheduling; new_first is a main load-command placement preference, not priority over dyld graph dependencies.
