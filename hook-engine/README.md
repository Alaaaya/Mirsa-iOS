Mirsa native hook compatibility shim, version 1.0.

This is a clean-room compatibility shim, not Cydia Substrate, libhooker, substitute or ElleKit itself. It is not a full jailbreak hooking engine. Never load a tweak from an untrusted source. Native code runs with the host app's privileges and can read that app's data or crash it. Merely changing library dependencies does not make arbitrary native code safe.

MSHookMessageEx and LBHookMessage use the Objective-C runtime. Inherited methods are installed on the requested class rather than mutating a superclass or sibling. Class-method hooks use the metaclass. An original IMP is published before replacement. Repeated hooks on the same class and selector chain through the previous implementation. Existing inherited IMPs are captured, not dynamic superclass-call trampolines. Changes made independently by another hooking runtime after installation are not coordinated.

MSHookFunction, LHHookFunctions and substitute_hook_functions only rebind legacy imported-symbol pointer slots in images already loaded. They never patch instructions. Exported targets must have an exact dladdr symbol and agree with global dlsym resolution. Stripped/local symbols, direct calls, saved function pointers, inlined functions and unresolved lazy import slots are not intercepted. The saved original remains callable but is not an executable trampoline.

An import is eligible only when its current resolved value matches the target or a preceding replacement made by this shim. This avoids silently rebinding unrelated same-name imports. Hooking a C function with zero actual changed pointers reports MIRSA_HOOK_UNSUPPORTED and clears original output, even if fishhook found image sections. Success reports MIRSA_HOOK_IMPORTS_REBOUND, never a claim that arbitrary calls were hooked.

arm64e image subtype (including capability bits), authenticated imports and any image containing LC_DYLD_CHAINED_FIXUPS are outside this implementation. Eligible legacy images can still be rebound while other images are skipped. JIT availability does not enable inline hooks. There is no inline patcher, disassembler, executable allocation, pointer-authentication trampoline, private symbol parser or future-image callback. The explicit memory/executable APIs fail closed. No EK-specific or native Swift ABI is claimed.

MirsaHookGetLastStatus, MirsaHookGetLastError and MirsaHookGetLastReboundCount are thread-local diagnostics. A memory-protection or allocation failure can occur after some imported pointers changed. The rebound count and original output remain available for that partial application. Wrapper batches are not all-or-nothing. Unsupported options are prevalidated before any hook in that batch. Hooks should be installed during initialization. Aligned import stores are atomic, but the whole set of images and externally modified methods are not a process-wide transaction. Keep loaded tweaks and their replacement functions alive while installed. There is no unhook/unload facility.

MSGetImageByName and wrapper image APIs only find already loaded exact paths. MSFindSymbol's non-NULL image scope is checked against the defining native image so dependencies cannot leak into a scoped lookup. MSImageRef is a borrowed header identity, and MSCloseImage does not dlclose it. LH/substitute wrapper objects own only their allocated wrapper state; substitute also retains an RTLD_NOLOAD handle. A concurrent third-party unload is not synchronized.

Run bash hook-engine/build.sh from the repository root on macOS with Xcode, or bash hook-engine/build-linux.sh on Linux with clang/LLD and an Apple SDK. On Linux, SDK defaults to /home/kit/drift-runtime25/iPhoneOS16.5.sdk, and CC defaults to clang-18. Set SDK and CC to override them. Device output is always arm64-apple-ios15.0, with install name @rpath/CydiaSubstrate.framework/CydiaSubstrate and explicit current/compatibility version 1.0.0. The result is ad-hoc signed for packaging and must be signed with the recipient app. Metadata, public headers, module map, combined attribution and SHA256SUMS are generated under hook-engine/dist. No secrets or certificate material are embedded.

Run bash hook-engine/test-macos.sh on macOS. Its private temporary directory never overwrites the committed device framework. It builds and executes Objective-C inheritance/sibling/chaining/metaclass assertions; a separately compiled dlopen-loaded Substrate tweak with a saved original; a real imported C provider with intercepted calls and callable originals; libhooker and substitute wrappers; scoped images; missing selectors and stripped/local targets; zero-import failures; and unchanged calls in a later-loaded importer. Positive tests explicitly disable chained fixups with -Wl,-no_fixup_chains. A separate executable explicitly enables chained fixups and verifies its calls remain unchanged with unsupported status.
