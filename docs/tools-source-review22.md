Research snapshot for 2026-11-22. This note records source-review evidence only. No font or audio binary was downloaded or installed, and this task made no source-code edits, commit, merge, or publication.

**Google Fonts** is the selected font source, restricted to families in its official `ofl` tree. The repository README explains that the top-level directories identify license families and each family has its own license file and metadata. The relevant official pages are [the repository](https://github.com/google/fonts), [the OFL directory](https://github.com/google/fonts/tree/main/ofl), and the [official OFL 1.1 text](https://openfontlicense.org/open-font-license-official-text/). Do not treat every family in Google Fonts as OFL. The same repository also contains Apache- and Ubuntu-licensed families, so the per-family `OFL.txt` and `METADATA.pb` must be checked before an item is listed.

The public GitHub Contents API works for a known family, for example `https://api.github.com/repos/google/fonts/contents/ofl/notosans?ref=main` and `https://api.github.com/repos/google/fonts/contents/ofl/notosansarabic?ref=main`. It returns the file names and official raw URLs. The `ofl` directory Contents response itself is capped at 1,000 entries and had no pagination Link header, so it is not a complete family index. A complete tree was verified through `https://api.github.com/repos/google/fonts/git/trees/6c7b4e8d707d00ee9b20d6166505a9fce236da9b?recursive=1`, which returned 17,378 paths with `truncated=false`. That tree SHA was obtained from the official root Contents response; the snapshot commit was `06bfe0d62a98375cb09c942fa18e68bd32cff057`. GitHub reported its unauthenticated core API limit as 60 requests per hour during this check, so cache tree and metadata responses and fetch only selected families' licenses and metadata.

The official Google Fonts Developer API is documented at [developers.google.com/fonts/docs/developer_api](https://developers.google.com/fonts/docs/developer_api) and uses `https://www.googleapis.com/webfonts/v1/webfonts?key=YOUR_API_KEY`. Google requires an API key, and its documented family response has styles, subsets, files, and version metadata but no license field. A no-key request returned 403. It is therefore not sufficient by itself for an OFL-only catalog. Use the official repository metadata and family license as the licensing authority, pin the repository commit for a reviewed catalog snapshot, and do not infer licenses from a font file URL alone.

Two concrete OFL candidates were checked. Noto Sans has `license: "OFL"` in [its METADATA.pb at the pinned commit](https://raw.githubusercontent.com/google/fonts/06bfe0d62a98375cb09c942fa18e68bd32cff057/ofl/notosans/METADATA.pb), and its [OFL.txt](https://raw.githubusercontent.com/google/fonts/06bfe0d62a98375cb09c942fa18e68bd32cff057/ofl/notosans/OFL.txt) and variable font [NotoSans[wdth,wght].ttf](https://raw.githubusercontent.com/google/fonts/06bfe0d62a98375cb09c942fa18e68bd32cff057/ofl/notosans/NotoSans%5Bwdth%2Cwght%5D.ttf) returned HTTP 200. Its metadata lists English, German, and Kurdish Latin. Noto Sans Arabic likewise declares OFL in [its METADATA.pb](https://raw.githubusercontent.com/google/fonts/06bfe0d62a98375cb09c942fa18e68bd32cff057/ofl/notosansarabic/METADATA.pb); its [OFL.txt](https://raw.githubusercontent.com/google/fonts/06bfe0d62a98375cb09c942fa18e68bd32cff057/ofl/notosansarabic/OFL.txt) and [NotoSansArabic[wdth,wght].ttf](https://raw.githubusercontent.com/google/fonts/06bfe0d62a98375cb09c942fa18e68bd32cff057/ofl/notosansarabic/NotoSansArabic%5Bwdth%2Cwght%5D.ttf) also returned HTTP 200. Its metadata includes `ckb_Arab` and `ku_Arab`, as well as Arabic and Latin subsets. These are promising candidates for the requested languages, not a claim of complete Sorani or Kurmanji rendering. Verify the actual required code points, shaping, and fallback on device before calling language coverage complete.

OFL 1.1 permits bundling, embedding, and redistribution with software, but the font cannot be sold by itself. Keep the copyright notice and license with each distributed font copy, keep any modified font under OFL, and do not reuse a Reserved Font Name if that family declares one. Treat each font file as its own item tied to its family metadata and license, not as a free-standing Google Fonts API result. For an item record, retain the exact upstream commit, family slug, exact file path, copyright line, license URL, and checksum when the item is actually reviewed. Do not present Google or a font author as endorsing Mirsa.

**Kenney Interface Sounds** is the selected audio source. Its official asset page is [kenney.nl/assets/interface-sounds](https://kenney.nl/assets/interface-sounds). The page identifies the Audio category, 100 assets, CC0, and version 1.0 released in 2020. Kenney's [support page](https://kenney.nl/support) says assets on its asset pages are CC0, may be used commercially, and do not require attribution; it recommends using the license file included with an asset package or its page. The license is [CC0 1.0](https://creativecommons.org/publicdomain/zero/1.0/) with its [legal code](https://creativecommons.org/publicdomain/zero/1.0/legalcode.en). The page's visible Download control points only to an inline section on the same page, not to a stable public archive URL or a machine-readable per-file feed. The separate All-in-1 link points to a much broader bundle and is not the selected source. The public page was readable through the page reader, but a command-line request from this sandbox returned 403; direct automated download access was not verified.

Kenney's page publishes a pack-level license and total count, not the 100 filenames, sizes, checksums, or per-file license records. Its hosted `preview.ogg` is a preview, not evidence of the downloaded pack's per-file format or inventory. Only files actually included in the verified Interface Sounds 1.0 package should be treated as covered by this source decision. Kenney's site terms say site materials are protected unless marked otherwise, so the CC0 mark on the asset page does not grant rights to the Kenney logo, page artwork, or unrelated site material. Do not mirror or rehost anything. Until a stable official download path and the archive's own license/readme can be inspected, the safe Tools Store behavior is a link to the official asset page, not an in-app file feed. If a later review receives the official package, record each exact filename, package version, source page, included license/readme, and checksum; attribution is optional, and Kenney says not to use its logo separately.

No named third-party repository was selected for app tweaks or deb/dylib browsing in this review, so none is approved here. Keep that work separate and opt-in, metadata-only, and linked to each original source, with per-source and per-item hide controls. Review benign app customization entries individually before exposing a download; do not catalog exploits, bypasses, piracy, or arbitrary binary execution/import.
