# Runtime translation v1 (branch only, not deployed)

One POST HTTPS endpoint, configured explicitly as RUNTIME_PUBLIC_ENDPOINT. Supabase gateway JWT verification must be disabled for this function only; function verifies bootstrap JWT itself. No endpoint defaults in clients.

All requests JSON, common fields action, bundleId (ASCII reverse-domain), revision (lowercase SHA256 of original app bytes), consent true. Unknown fields rejected. Errors {"error":"code"} with 400/401/403/413/429/503. Never replace original text on error. No user text logged. Only consented safe UI labels are durably stored in the scoped translation queue; event payloads contain metadata only.

Mirsa bootstrap uses Authorization: Bearer <Supabase user access JWT>. Never embed this JWT in signed app.
Dictionary request {"action":"dictionary","bundleId":"com.example.app","revision":"64 lowercase hex","consent":true,"items":[{"id":"s0","text":"设置"}]}.
Dictionary response {"bundleId":"com.example.app","revision":"...","translations":{"s0":"الإعدادات"}}. Items up to 128, each 256 UTF16 units, combined 8192. Only safe UI strings, not arbitrary documents. Rejected sensitive items cause whole request rejection.

Capability request {"action":"issue","bundleId":"com.example.app","revision":"...","consent":true}.
Response {"online":{"endpoint":"https://.../runtime-translate","token":"mrt1.<64 random lowercase hex>","bundleId":"com.example.app","revision":"...","expiresAt":"ISO8601 UTC"}}.
Capabilities live 24 hours, scoped to authenticated user/app/revision, stored as SHA256 digest only, never general auth tokens. Issue quota 12/day/user prevents quota reset via unlimited tokens. Capabilities cannot call dictionary or issue. Offline dictionary continues after expiry; no runtime JWT refresh.

Runtime request Authorization: Bearer <online.token>.
{"action":"missing","bundleId":"com.example.app","revision":"...","consent":true,"items":[{"id":"s0","text":"设置"}]}
Response {"bundleId":"com.example.app","revision":"...","translations":{"s0":"الإعدادات"}}.
Missing batch max 16, each 256 UTF16 units, total 2048, only strings containing CJK. Runtime client should deduplicate, debounce, send only strings absent from local dictionary, never block render thread. Cache by exact original string and app/revision locally; only apply translations for returned IDs matching sent originals. No text loss if subset omitted.
Server rejects email, URLs/domains, paths, credentials, long digit sequences, private-data markers and unsafe controls before provider. Privacy screening is conservative but cannot prove arbitrary text contains no names; explicit per-app online consent required, online off by default.
Durable atomic quotas before provider: 10 requests/minute and 256 requests/32768 chars per capability lifetime; user 100 requests/65536 chars daily (all actions). Failures consume reserved quota. Auth rate scope is user, never client-supplied ID. Scope mismatch/revocation/expiry denied. Tokens are bearer secrets, do not put in logs or URLs.

Output Arabic only when safe and placeholders preserved byte-for-byte, source IDs unchanged; unsafe/malformed provider results omitted. Max HTTP body 48KiB, max response 48KiB; provider response 64KiB and each returned translation 1024 units; whole handler 25s, provider total 18s.
No model fallback. The only approved translation route is exact gemini-2.5-flash at https://generativelanguage.googleapis.com/v1beta/openai, explicitly present in the server model/origin allowlists. All other models and origins are rejected, including other Flash/Lite models. Returned provider model identity must also match. Config without approved credentials/model/provider returns 503.

## Isolated WEB staging, 2026-11-25

staging.ts is opt-in only, requires RUNTIME_STAGING_ONLY=true, and uses the shared request handler with a local-only database/auth adapter. It never calls production Supabase, uses no production secret, and must never be deployed as a production Edge Function. The separate Postgres listens on a private Unix socket only. Ops directory permissions are 0700, secret/fixture files 0600, and the server has a dedicated init.sh startup entry. No production schema or auth settings were changed.

Staging authenticates only independently issued HS256 bootstrap JWTs, verified with maintained jose and a separate server-only secret of at least 64 bytes. Claims must include the fixed isolated test subject, issuer urn:mirsa:runtime-staging25, audience mirsa-runtime-staging25, scope runtime:bootstrap, unique jti, iat and exp, maximum age/lifetime one hour. Normal production login JWTs are not accepted. There is no public mint/login endpoint. A session must be explicitly imported at runtime or passed through private CI launch configuration. Never compile a bootstrap JWT or signing/provider secret into any IPA, app bundle, fixture resources or source control. Only the short-lived per-app mrt1 missing-label capability may enter a translated target app after consent.

The public HTTPS endpoint is an explicit non-secret configuration value supplied in the private staging handoff, with a unique exact path. Global staging admission limits add four active requests and sixty requests per minute before auth; durable owner/app limits remain in force. Missing-token scope is a bearer restriction, not app attestation. Offline dictionaries must continue unchanged on any network, token, provider or quota failure. Staging bootstrap provisioning is not implemented for ordinary device sessions; without an explicitly provisioned test session, keep online off, use pre-generated dictionaries, and do not claim the owner IPA has functioning online generation.
